# Стартовый пакет дизайн-системы

Правила для Claude и готовый проект: HTML + Nunjucks + Tailwind CSS v4 + Vite, канва для клиента, проверки
качества. Дизайн приходит из Claude Design, итог переносится в Nuxt 4 + Vue 3.5 + Reka UI.
Правила и команды — на английском; Claude отвечает дизайнеру на его языке.

## Как запустить новый проект

1. Создайте пустую папку проекта и распакуйте в неё этот архив целиком (вместе со скрытой папкой `.claude`).
2. Если бренд уже есть в Claude Design — держите под рукой ссылку на его дизайн-систему или макет в Claude
   (или положите экспорт в папку `design-import/` внутри проекта). Можно и без него: останутся временные цвета,
   бренд применится позже.
3. Откройте папку в Claude Code и введите команду `/bootstrap`.
4. Ответьте на вопросы: название продукта, язык интерфейса, валюта, бренд (ссылка или экспорт), шрифт.

Дальше Claude сам: запишет настройки, переведёт цвета бренда в токены и проверит контраст, установит
зависимости, прогонит все проверки, сделает первый коммит и откроет канву на http://localhost:5173.
Нужны только Node.js 20.19+ и Git — если их нет, `/bootstrap` скажет, что установить.

## Как работать дальше: дизайн — в Claude Design, система — здесь

Вы продолжаете рисовать в канве Claude Design, как привыкли. Код руками не трогаете. Claude Design теперь живёт
внутри Claude: макет — это артефакт со своей ссылкой (отдельный сайт claude.ai/design закрывается 14 декабря 2026).

1. **Claude Design.** Делаете или меняете экраны.
2. **Ссылка.** У макета Share → Copy link (или адрес страницы макета из браузера). Экспорт .zip тоже
   подходит — положите его в `design-import/`.
3. **Перенос.** В Claude Code вводите `/import-design` и вставляете ссылку (или пишете «перенеси макет <ссылка>»).
   Claude прочитает макет, сравнит с прошлым переносом, разложит изменения по токенам, компонентам и экранам,
   проверит доступность и контраст, запишет всё в `IMPORTS.md` и сделает коммит.
4. **Канва.** Смотрите результат на http://localhost:5173. В отчёте Claude перечислит, что появилось, какие
   значения он округлил до токенов и что не перенёс (например, слабый контраст) — с объяснением.
5. **Поправки** вносите снова в Claude Design и повторяете шаги 2–4.

Что за системой и никогда не перезапишется переносом: состояния данных, доступность, контраст, контракт
данных и параметры компонентов.

**Обратно в Claude Design.** Команда `/publish-design-system` публикует систему из репозитория в Claude как
дизайн-систему: токены светлой и тёмной темы, типографику, отступы, радиусы, компоненты с превью и правила.
Выберите её в меню дизайн-системы при создании макета (или сделайте системой по умолчанию) — тогда новые экраны
сразу рисуются в токенах проекта, и при переносе почти ничего не округляется. Запускайте после первого
`/bootstrap` и после переносов, которые меняют токены или компоненты.

Можно и просто просить Claude словами, например: «Сделай недостающие базовые компоненты из components.md §8»
или «Сделай контракт данных для сущности „Сделка“». После каждой правки Claude сам запускает проверки и
исправляет найденное.

На канве слева — навигация по флоу, экранам и компонентам. У экранов и компонентов с данными над фреймом
есть вкладки состояний: Default, Loading, Empty, No results, Error, Stress — только те, что к ним применимы.

Чтобы утвердить экран, поставьте ему `"status": "approved"` в `src/canvas.json` и выполните
`npm run approve:visual` — с этого момента любое изменение экрана будет заметно в проверках.

## Что внутри

```text
├── AGENTS.md, CLAUDE.md       # главные правила для агентов
├── IMPORTS.md                 # журнал переносов из Claude Design
├── design-import/             # макеты, прочитанные из Claude Design (по папке на перенос, в git не попадает)
├── .claude/
│   ├── rules/                 # 8 тематических правил: токены, компоненты, экраны, доступность, UX, паттерны,
│   │                          # локализация, контракт данных
│   ├── skills/                # команды /bootstrap, /import-design, /publish-design-system
│   └── settings.json          # автопроверка после каждой правки + разрешения на npm/git
├── index.html, viewer/        # канва
├── build/                     # сборка шаблонов Nunjucks
├── scripts/                   # проверки данных, реестра и контраста
├── tests/                     # доступность (axe) и скриншоты утверждённых экранов
└── src/
    ├── project.json           # настройки проекта (заполняет /bootstrap)
    ├── styles/tokens.css      # цвета: палитра → семантические токены → тёмная тема
    ├── layouts/               # оболочки страниц и матриц
    ├── components/            # 5 эталонных компонентов: BaseButton, BaseIconButton, BaseBadge, BaseInput, FormField
    ├── pages/, data/          # экраны и данные проекта (пока пусто)
    ├── components.json        # реестр компонентов
    └── canvas.json            # какие экраны показывать на канве
```

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | канва с автообновлением |
| `npm run verify` | все проверки разом: данные, контраст, классы, сборка, доступность |
| `npm run approve:visual` | записать эталонные скриншоты утверждённых экранов |
| `npm run design-system` | собрать файлы дизайн-системы для `/publish-design-system` |

## Чего пока нет

- Скиллы `new-component` и `new-screen` — пока Claude делает это по правилам.
- На канве нет эмуляции наведения и фокуса, режима инспектора и комментариев-пинов (наведение и фокус
  проверяются прямо во фрейме мышью и клавишей Tab).
- Нет CI в GitHub и превью-ссылок для клиента — канва открывается локально.

## Как менять правила

- У пакета один владелец; изменения — через PR в репозиторий стартового пакета, не в проектах.
- `AGENTS.md` не длиннее 150 строк: всё тематическое — в `.claude/rules/`.
- Если правило можно проверить автоматически, сначала добавьте проверку, потом текст.
- Раз в спринт запускайте `/doctor prompt-audit` в Claude Code — он ищет противоречия между файлами правил.
